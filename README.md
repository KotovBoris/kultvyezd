# КультВыезд

Сервис для классного руководителя: собрать группу на культурный выезд в MAX.
Учитель выбирает событие, родители отвечают в боте или в мини-приложении, на экране видно, кто едет, и скачивается проект приказа.

Билет родитель покупает на сайте музея. Деньги через сервис не проходят.

## 1. Назначение

Школьный выезд на мероприятие (музей, театр, событие по «Пушкинской карте») обычно живёт в чате класса и в таблице. КультВыезд закрывает этот кусок: от карточки события до списка группы и черновика приказа.

Приоритетный пользователь — классный руководитель. Родитель отвечает по своему ребёнку. Завуч забирает документ.

## 2. Основной сценарий

1. Учитель открывает мини-приложение из бота MAX (локально — в браузере).
2. В каталоге включает «Пушкинская карта» и создаёт выезд на класс.
3. Родитель нажимает «Отпускаю ребёнка» или «Не сможет поехать».
4. Повторный ответ по тому же ребёнку первый не затирает.
5. Учитель смотрит статусы и напоминает тем, кто ещё не ответил или не отметил билет.
6. Скачивает DOCX и PDF: проект приказа, список согласившихся, реестр ответов, лист инструктажа.

В чате бота родитель может посмотреть свои выезды (`/trips`) и ответить кнопкой.

## 3. Состав и архитектура

Два контейнера.

- `backend` — FastAPI, правила выезда, адаптер бота MAX, генерация DOCX и PDF, SQLite.
- `miniapp` — React и MAX UI, nginx раздаёт статику и проксирует `/api` на backend.

Бот живёт в том же процессе, что и API. Без токена MAX он не стартует, остальное работает.

Подробнее: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## 4. Запуск одной командой

Из каталога проекта:

```bash
docker compose up --build
```

Нужен Docker с плагином Compose. Файл переменных можно не создавать: пустой токен уже заложен в `compose.yaml`. Для живого бота скопируйте `.env.example` в `.env` и впишите `MAX_BOT_TOKEN`.

## 5. Что нужно на машине

- Docker и Docker Compose.
- Для проверки в самом мессенджере: аккаунт MAX, токен бота и публичный HTTPS-адрес мини-приложения. Локальный `localhost` кнопка «Открыть приложение» внутри MAX не откроет.
- Отдельные логины и пароли не нужны.

## 6. Переменные окружения

Образец: [.env.example](.env.example). Рабочих токенов в репозитории нет.

| Переменная | Зачем | По умолчанию |
|---|---|---|
| `MAX_BOT_TOKEN` | токен бота | пусто, бот выключен |
| `MAX_API_BASE` | адрес Bot API | `https://platform-api2.max.ru` |
| `MAX_BOT_MODE` | `polling`, `webhook` или `off` | `polling` |
| `MAX_BOT_USERNAME` | ник бота для кнопки и ссылок | `t158_hakaton_max_bot` |
| `MAX_WEBHOOK_URL`, `MAX_WEBHOOK_SECRET` | только для режима webhook | пусто |
| `MAX_CA_BUNDLE` | сертификаты для TLS до MAX | `/certs/ca-bundle.pem` |
| `MAX_TLS_INSECURE` | не проверять TLS, только для отладки | `0` |
| `DATABASE_URL` | файл SQLite | `sqlite:////app/data/kultvyezd.db` |
| `AUTO_SEED` | положить демо-данные при старте | `true` |
| `MINIAPP_BASE_URL`, `PUBLIC_BASE_URL` | ссылки на файлы | `http://localhost:8080` |
| `LOG_LEVEL` | уровень логов | `INFO` |

Ник бота после создания в MAX не меняется.

## 8. Зависимости

Версии зафиксированы.

- Python: [backend/requirements.txt](backend/requirements.txt). Образ `python:3.12-slim`. SQLAlchemy держим на 2.0.35: более новая ломает связи SQLModel 0.0.22.
- Мини-приложение: [miniapp/package-lock.json](miniapp/package-lock.json). Образ `node:20-alpine`, отдача через `nginx:1.27-alpine`.

## 9. Внешние сервисы

| Сервис | Как подключён |
|---|---|
| MAX Bot API, `platform-api2.max.ru` | живой, если задан токен. Иначе бот не запускается |
| MAX Bridge в мини-приложении | данные пользователя и скачивание файла, когда страница открыта внутри MAX |
| Каталог PRO.Культура.РФ | не подключён. Вместо него подготовленный список событий Казани |
| Касса музея | ссылка наружу. Оплату сервис не проводит |

Если токена нет, основной сценарий учителя и родителя проверяется на http://localhost:8080 без мессенджера.

## 10. Данные

SQLite, файл в volume `kultvyezd-data`. Схема создаётся при старте.

В базе: класс, ученики, телефоны родителей, события, выезды, статусы, журнал ответов, файлы приказов.

Каталог помечен как подготовленные данные: поле `source` у события и `dataset.is_mock: true` в `GET /api/v1/meta`.

ФИО и телефоны в демо выдуманы.

Ответ родителя — запись, кто нажал, когда и из какого канала (бот, мини-приложение, API). Это не квалифицированная электронная подпись.

Вне MAX на странице есть блок «Режим просмотра»: можно открыть экран любого родителя и вернуть статусы в «ожидает».

## 12. Как проверить

1. `docker compose up --build`
2. Открыть http://localhost:8080. Внизу страницы написано, что каталог модельный.
3. Вкладка «Каталог событий», фильтр «Пушкинская карта», «Выбрать событие», «Создать выезд». Появляется карточка выезда.
4. «Напомнить не ответившим». В ответе два числа: скольким надо напомнить и скольким сообщение ушло. Без токена и без привязки родителя к боту второе число равно нулю.
5. «Сформировать приказ (DOCX)» или PDF. Файл скачивается.
6. «Режим просмотра» → выбрать ученика → «Отпускаю ребёнка». Появляется текст, что согласие подписано, с именем и временем.
7. Нажать ещё раз. Текст, что согласие уже подписано, статус не меняется.
8. Вернуться к учителю: статус этого ученика другой.
9. http://localhost:8080/docs открывает Swagger.
10. В MAX: бот https://max.ru/t158_hakaton_max_bot , кнопка «Начать». Ожидается приветствие и кнопки «Открыть приложение» и «Мои выезды». Кнопка приложения сработает, когда у бота прописан публичный HTTPS.

Команды самопроверки, без Docker:

```bash
cd backend && python3.12 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m pytest -q
cd ../miniapp && npm ci && npm test
```

Сквозной прогон бота на эмуляторе протокола: `python scripts/e2e_agent.py` из корня, тем же интерпретатором, где стоят зависимости backend.

## 13. Что система отвечает

`GET /healthz` без токена (режим по умолчанию `polling`):

```json
{"status":"ok","version":"1.0.0","bot_mode":"polling","bot_enabled":false}
```

В ответе также есть поле `time`. С токеном `bot_enabled` становится `true`.

Повторное согласие:

```json
{"changed": false, "message": "Согласие уже подписано (..., ...). Статус: Едет."}
```

Сводка выезда содержит ключи `GREEN`, `YELLOW`, `GREY`, `RED`.

- зелёный: родитель согласен, билет не нужен или уже отмечен купленным;
- жёлтый: согласен, билет ещё не отмечен;
- серый: ответа нет;
- красный: отказ.

В приказ попадают только те, кто согласен. Отказы видны на экране учителя и в приказ не входят.

## 14. Ограничения

- Каталог сам не обновляется.
- В демо нет ролей на API: ручки открыты, чтобы сценарий можно было пройти. Для боя включается проверка `initData` (`MAX_VALIDATE_INIT_DATA`).
- Дедлайн показывается, но просроченный ответ сервис не отклоняет.
- Напоминание считается доставленным только если у родителя есть `max_user_id` и бот включён.
- Текст приказа — шаблон. Перед подписью его смотрит школа.
- Импорт класса каждый раз создаёт новый класс и пропускает кривые строки, а не отвергает весь файл.

## 15. Остановка и повторный запуск

```bash
docker compose down
docker compose up --build
```

Убрать данные и начать с чистого демо:

```bash
docker compose down -v
docker compose up --build
```

Только перезапуск API, без пересборки: `docker compose restart backend`.
