# ClassGo

Сервис для классного руководителя: собрать группу на культурный выезд в MAX.
Учитель выбирает событие, родители отвечают в боте или в мини-приложении, на экране видно, кто едет, и скачивается проект приказа.

Билет родитель покупает на сайте музея. Деньги через сервис не проходят.

## 1. Назначение

Школьный выезд на мероприятие (музей, театр, событие по «Пушкинской карте») обычно живёт в чате класса и в таблице. ClassGo закрывает этот кусок: от карточки события до списка группы и черновика приказа.

Приоритетный пользователь — классный руководитель. Родитель отвечает по своему ребёнку. Завуч забирает документ.

## 2. Основной сценарий

По умолчанию приложение открывается в режиме родителя: лента заявок по его детям.
Кнопка «Я учитель» переключает в режим учителя; любой пользователь может быть учителем.

Учитель:

1. В разделе «Классы» создаёт класс вручную или загружает CSV/XLSX, привязывает школу
   (поиск по зарегистрированным), указывает чат класса, делится доступом с другими
   учителями (чтение или редактирование).
2. Рассылает родителям ссылки-приглашения; родитель подтверждает в боте, что ребёнок его.
3. Нажимает «Создать мероприятие» и проходит четыре шага: класс и школа → событие из
   каталога с фильтрами → время и дедлайн → проверка и запуск. После запуска анонс уходит
   в чат класса, родителям с активированным ботом — рассылка.
4. На дашборде видит по каждому ребёнку статус родителя: аппрувнул, отказал, не ответил,
   бот не активирован. Неактивировавших можно тегнуть списком в чате класса.
5. Скачивает DOCX и PDF: проект приказа, список согласившихся, реестр ответов, лист инструктажа.

Родитель:

1. Видит ленту заявок по своим детям, отвечает «Отпускаю ребёнка» или «Не сможет поехать».
2. Если родителей двое, второй видит ответ первого; повторный ответ первый не затирает.
3. Может отказаться от рассылки по всем мероприятиям (в приложении или командой `/mute` в боте).
4. Автонапоминания без ответа приходят за 3 дня, за день и за 12 часов до дедлайна.

В чате бота родитель может посмотреть свои выезды (`/trips`) и ответить кнопкой.

## 3. Состав и архитектура

Два контейнера.

- `backend` — FastAPI, правила выезда, адаптер бота MAX, генерация DOCX и PDF, SQLite.
- `miniapp` — React и MAX UI, nginx раздаёт статику и проксирует `/api` на backend.

Бот живёт в том же процессе, что и API. Без токена MAX он не стартует, остальное работает.

Подробнее: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## 4. Запуск одной командой

Из каталога проекта:

```bash
docker compose up --build
```

Нужен Docker с плагином Compose. Файл переменных можно не создавать: пустой токен уже заложен в `compose.yaml`. Для живого бота скопируйте `.env.example` в `.env` и впишите `MAX_BOT_TOKEN`.

## 5. Что нужно на машине

- Docker и Docker Compose.
- Для проверки в самом мессенджере: аккаунт MAX, токен бота и публичный HTTPS-адрес мини-приложения. Локальный `localhost` кнопка «Открыть приложение» внутри MAX не откроет.
- Отдельные логины и пароли не нужны.

## 6. Переменные окружения

Образец: [.env.example](.env.example). Рабочих токенов в репозитории нет.

| Переменная | Зачем | По умолчанию |
|---|---|---|
| `MAX_BOT_TOKEN` | токен бота | пусто, бот выключен |
| `MAX_API_BASE` | адрес Bot API | `https://platform-api2.max.ru` |
| `MAX_BOT_MODE` | `polling`, `webhook` или `off` | `polling` |
| `MAX_BOT_USERNAME` | ник бота для кнопки и ссылок | `t158_hakaton_max_bot` |
| `MAX_WEBHOOK_URL`, `MAX_WEBHOOK_SECRET` | только для режима webhook | пусто |
| `MAX_CA_BUNDLE` | сертификаты для TLS до MAX | `/certs/ca-bundle.pem` |
| `MAX_TLS_INSECURE` | не проверять TLS, только для отладки | `0` |
| `DATABASE_URL` | файл SQLite | `sqlite:////app/data/classgo.db` |
| `AUTO_SEED` | положить демо-данные при старте | `true` |
| `MINIAPP_BASE_URL`, `PUBLIC_BASE_URL` | ссылки на файлы | `http://localhost:8080` |
| `LOG_LEVEL` | уровень логов | `INFO` |

Ник бота после создания в MAX не меняется.

## 9. Внешние сервисы

| Сервис | Как подключён |
|---|---|
| MAX Bot API, `platform-api2.max.ru` | живой, если задан токен. Иначе бот не запускается |
| MAX Bridge в мини-приложении | данные пользователя и скачивание файла, когда страница открыта внутри MAX |
| Каталог PRO.Культура.РФ | не подключён. Вместо него подготовленный список событий Казани |

Если токена нет, основной сценарий учителя и родителя проверяется на http://localhost:8080 без мессенджера.

## 10. Данные

SQLite, файл в volume `classgo-data`. Схема создаётся при старте.

В базе: класс, ученики, телефоны родителей, события, выезды, статусы, журнал ответов, файлы приказов.

Каталог помечен как подготовленные данные: поле `source` у события и `dataset.is_mock: true` в `GET /api/v1/meta`.

ФИО и телефоны в демо выдуманы.

Ответ родителя — запись, кто нажал, когда и из какого канала (бот, мини-приложение, API). Это не квалифицированная электронная подпись.

## 12. Как проверить

Публичный стенд: https://213.193.198.71 (самоподписанный сертификат — браузер попросит подтвердить исключение). Локально — те же шаги на http://localhost:8080.

Прогон за учителя (регистрация с нуля не нужна — учителем может стать любой пользователь):

1. `docker compose up --build`, открыть http://localhost:8080.
2. Приложение откроется в режиме родителя; нажать «Я учитель».
3. Вкладка «Классы»: видны демо-классы (8Б, 5А, 7В). «Создать вручную» — заполнить параллель,
   литеру, учеников строками «ФИО; телефон», выбрать или добавить школу, «Создать класс».
   Созданный класс принадлежит текущему пользователю: другие видят его только после шаринга.
4. В карточке класса: «Открыть» — добавить ученика, указать ID чата класса, «Пригласить
   родителя» (создаётся ссылка на бота), «Поделиться классом» по MAX user_id.
5. Вкладка «Мероприятия» → «Создать мероприятие»: шаг 1 класс, шаг 2 событие (фильтр
   «Пушкинская карта»), шаг 3 время и дедлайн, шаг 4 «Запустить мероприятие».
6. На дашборде: колонка «Родитель» со статусами, «Напомнить не ответившим», «Тегнуть не
   активировавших бота», «Анонс в чат класса» (нужен указанный чат), «Сформировать приказ (DOCX)» и PDF.

Прогон за родителя:

1. Открыть приложение без параметров. Неизвестному пользователю показывается блок
   «Найти себя в базе»: ввести фамилию родителя, телефон или ФИО ребёнка и нажать
   «Это я» — лента заявок привяжется к текущему пользователю (внутри MAX — к его
   настоящему id, в браузере — к сохранённому демо-идентификатору).
2. Либо открыть заранее привязанного демо-родителя: http://localhost:8080/?user_id=1001 —
   лента по двум детям; http://localhost:8080/?user_id=1003 — карточка «Подтвердите привязку»
   с кнопками «Да, это мой ребёнок» / «Нет, это ошибка».
3. «Отпускаю ребёнка» — согласие фиксируется с именем и временем; повторное нажатие статус не меняет.
4. Если родителей двое, второму придёт сообщение бота о решении первого, в ленте виден ответ.
5. «Отказаться от рассылки по всем мероприятиям» — напоминания и рассылки больше не приходят
   (в боте то же самое делает `/mute`, возврат — `/unmute`).
6. В MAX: бот https://max.ru/t158_hakaton_max_bot , кнопка «Начать». Ожидается приветствие и
   кнопки «Открыть приложение» и «Мои выезды». Кнопка приложения сработает, когда у бота прописан публичный HTTPS.

Команды самопроверки, без Docker:

```bash
cd backend && python3.12 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m pytest -q
cd ../miniapp && npm ci && npm test
```

Сквозной прогон бота на эмуляторе протокола: `python scripts/e2e_agent.py` из корня, тем же интерпретатором, где стоят зависимости backend.

## 13. Что система отвечает

`GET /healthz` без токена (режим по умолчанию `polling`):

```json
{"status":"ok","version":"1.0.0","bot_mode":"polling","bot_enabled":false}
```

В ответе также есть поле `time`. С токеном `bot_enabled` становится `true`.

Повторное согласие:

```json
{"changed": false, "message": "Согласие уже подписано (..., ...). Статус: Едет."}
```

Сводка выезда содержит ключи `GREEN`, `YELLOW`, `GREY`, `RED`.

- зелёный: родитель согласен, билет не нужен или уже отмечен купленным;
- жёлтый: согласен, билет ещё не отмечен;
- серый: ответа нет;
- красный: отказ.

В приказ попадают только те, кто согласен. Отказы видны на экране учителя и в приказ не входят.

## 14. Ограничения

- Каталог сам не обновляется.
- «Найти себя в базе» — демо-упрощение для проверки без приглашений: любой пользователь может
  привязаться к любому родителю из базы. В бою привязка идёт только по ссылке-приглашению
  от учителя с подтверждением в боте.
- Схема SQLite при обновлении дополняется автоматически (новые таблицы и колонки);
  полноценных миграций данных нет.
- В демо нет ролей на API: ручки открыты, чтобы сценарий можно было пройти. Для боя включается проверка `initData` (`MAX_VALIDATE_INIT_DATA`). Права на классы и школы (владелец, чтение, редактирование) при этом уже работают: сущности без владельца из демо-данных может править любой.
- Бот пишет только тем, кто сам начал с ним диалог: до активации бота родителем сервис показывает статус «бот не активирован», доставка невозможна — это ограничение платформы MAX.
- Автонапоминания (за 3 дня, день, 12 часов) рассылает фоновый цикл; без токена бота он выключен, интервал проверки — `REMINDER_INTERVAL_SECONDS`.
- Дедлайн показывается, но просроченный ответ сервис не отклоняет.
- Напоминание считается доставленным только если у родителя есть `max_user_id` и бот включён.
- Текст приказа — шаблон. Перед подписью его смотрит школа.
- Импорт класса каждый раз создаёт новый класс и пропускает кривые строки, а не отвергает весь файл.

## 15. Остановка и повторный запуск

```bash
docker compose down
docker compose up --build
```

Убрать данные и начать с чистого демо:

```bash
docker compose down -v
docker compose up --build
```

Только перезапуск API, без пересборки: `docker compose restart backend`.
