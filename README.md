# ClassGo

**Команда: КАРАГАНДА-М**

**Трек: «Досуг и развлечения» — MAX × Минобрнауки России**

ClassGo помогает классному руководителю организовать школьный культурный выезд внутри MAX: выбрать событие, собрать ответы родителей, проверить готовность класса и сформировать документы.

- Репозиторий: [github.com/KotovBoris/kultvyezd](https://github.com/KotovBoris/kultvyezd)
- Бот: [@t158_hakaton_max_bot](https://max.ru/t158_hakaton_max_bot)
- Формат сдачи: PDF-презентация, зафиксированная версия исходников и работающий основной сценарий в MAX
- Интерфейс после локального запуска: [localhost:8080](http://localhost:8080)
- Swagger после локального запуска: [localhost:8080/docs](http://localhost:8080/docs)

## 1. Назначение решения

При подготовке выезда учитель собирает ответы в чате, сверяет согласия и билеты, ведёт список участников и переносит сведения в документы. ClassGo объединяет эти действия вокруг одного выезда.

**Основной пользователь:** классный руководитель.

**Вторая роль:** родитель или законный представитель ребёнка.

Результат для учителя — ведомость готовности класса, адресные напоминания и пакет документов. Родитель видит условия поездки, подтверждает участие или отказывается, затем отмечает покупку билета.

Сервис не принимает оплату. Билеты покупают непосредственно на сайте учреждения культуры. Каталог MVP содержит модельные данные, а не актуальный поток событий из внешнего API.

## 2. Основной пользовательский сценарий

### Учитель

1. Открывает мини-приложение из бота MAX.
2. Импортирует класс из CSV/XLSX или использует демонстрационный 8-Б.
3. Выбирает событие в каталоге: доступны фильтры по дате, возрастному цензу, стоимости и признаку «Пушкинская карта», сортировка и подбор по возрасту класса.
4. Создаёт выезд с датой, временем сбора и возвращения, дедлайном ответа.
5. Публикует карточку выезда в чат класса.
6. Проверяет ведомость «Светофор» и отправляет напоминания родителям, от которых ждёт ответ или отметку о билете.
7. Формирует приказ и выбранные приложения в DOCX/PDF. Может отправить документ файлом в MAX, выгрузить список в CSV и скачать календарь ICS.

### Родитель

1. Открывает карточку поездки и экран своего ребёнка.
2. Подтверждает участие через отдельный шаг подтверждения и согласие на обработку данных либо указывает отказ и причину.
3. При необходимости переходит на сайт учреждения культуры за билетом.
4. Отмечает «Билет куплен» и при желании вводит номер билета.
5. Просматривает памятку, контакты и добавляет поездку в календарь.

Поддерживаются несколько детей у родителя и несколько законных представителей у ученика. Повторное решение не перезаписывает уже зафиксированный ответ.

### Статусы «Светофора»

| Статус | Значение |
|---|---|
| Зелёный: готов | Участие подтверждено, билет отмечен как купленный или не требуется |
| Жёлтый: ждём билет | Участие подтверждено, отметки о покупке пока нет |
| Серый: нет ответа | Родитель ещё не подтвердил участие и не отказался |
| Красный: отказ | Участие отклонено |

Отметку о покупке вводит пользователь. В MVP сервис не проверяет факт оплаты через билетного оператора.

## 3. Состав и архитектура решения

Модульный монолит с отдельным frontend-контейнером. Бот и мини-приложение используют одну бизнес-логику и одно хранилище.

| Компонент | Технологии | Назначение |
|---|---|---|
| Backend | Python, FastAPI, SQLModel/SQLAlchemy | REST API, бизнес-правила, адаптер MAX, документы |
| Mini-app | React, TypeScript, Vite, MAX Bridge, `@maxhub/max-ui` | Экраны учителя и родителя |
| Веб-сервер | nginx | Статика mini-app и проксирование API на backend |
| Хранилище | SQLite по умолчанию | Классы, ученики, контакты, выезды, ответы, журнал действий |
| Дополнительная БД | PostgreSQL, профиль Compose `postgres` | Альтернативная конфигурация развёртывания |

Основные исходники:

- `backend/app/main.py` — REST API и запуск приложения.
- `backend/app/services.py` — согласия, билеты, статусы и напоминания.
- `backend/app/bot.py`, `max_client.py` — сценарии и клиент MAX Bot API.
- `backend/app/documents.py` — генерация DOCX/PDF.
- `backend/app/models.py`, `schemas.py` — модели и контракты.
- `backend/app/max_validate.py` — проверка подписи стартовых данных MAX.
- `miniapp/src/screens/` — пользовательские экраны.
- `miniapp/src/api.ts`, `max.ts` — REST-клиент и обёртка MAX Bridge.

Подробнее: [ARCHITECTURE.md](docs/ARCHITECTURE.md).

## 4. Запуск всех локальных компонентов

Требуются Git и Docker с командой `docker compose`. Node.js и Python на компьютере не нужны для запуска контейнерного стека.

```bash
git clone https://github.com/KotovBoris/kultvyezd.git
cd kultvyezd
cp .env.example .env
docker compose up -d --build
```

Для работы бота заполните `MAX_BOT_TOKEN` в `.env`. Без токена REST API и браузерный режим mini-app доступны, но отправка сообщений в MAX не работает.

Проверка готовности:

```bash
curl http://localhost:8080/healthz
docker compose ps
```

По регламенту сборка должна занимать не более 5 минут без первоначальной загрузки базовых образов. Время сборки конкретного окружения следует проверить перед сдачей.

Дождитесь ответа `status: ok`, затем откройте [http://localhost:8080](http://localhost:8080).

При проблемах посмотрите логи:

```bash
docker compose logs --tail=100 backend miniapp
```

### Запуск с PostgreSQL

Для локальной демонстрации `.env.example` задаёт БД, пользователя и пароль `classgo`. Соответствующая строка подключения:

```dotenv
DATABASE_URL=postgresql+psycopg2://classgo:classgo@db:5432/classgo
```

Эта учётная запись предназначена для локального демо. При размещении на сервере замените пароль одновременно в `POSTGRES_PASSWORD` и `DATABASE_URL`.

Затем запустите:

```bash
docker compose --profile postgres up -d --build
```

SQLite и PostgreSQL используют разные тома. Переключение конфигурации не переносит существующие данные автоматически.

## 6. Параметры окружения

Пример конфигурации: [`.env.example`](.env.example). Рабочие секреты передают через окружение, а не добавляют в Git.

| Переменная | Назначение |
|---|---|
| `MAX_BOT_TOKEN` | Токен бота; необходим для взаимодействия с MAX |
| `MAX_BOT_USERNAME` | Имя бота, по умолчанию `t158_hakaton_max_bot` |
| `MAX_API_BASE` | Базовый адрес MAX Bot API |
| `MAX_BOT_MODE` | `polling`, `webhook` или `off` |
| `MAX_WEBHOOK_URL` | Публичный адрес `/webhook/max` для режима webhook |
| `MAX_WEBHOOK_SECRET` | Секрет проверки входящих webhook-запросов |
| `MAX_CA_BUNDLE` | Путь к CA-bundle для запросов к MAX; в примере `/certs/ca-bundle.pem` |
| `MAX_TLS_INSECURE` | Отключение проверки TLS; для обычного запуска оставьте `0` |
| `DATABASE_URL` | Строка подключения к SQLite или PostgreSQL |
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` | Настройки контейнера PostgreSQL |
| `MINIAPP_BASE_URL` | Базовый адрес мини-приложения |
| `PUBLIC_BASE_URL` | Базовый адрес абсолютных ссылок на документы |
| `AUTO_SEED` | Создание демонстрационных данных при старте |
| `LOG_LEVEL` | Уровень логирования |

В backend есть настройка `MAX_VALIDATE_INIT_DATA`, по умолчанию выключенная. Текущий `compose.yaml` не передаёт её в контейнер. Проверка подписи согласия сама по себе не обеспечивает полноценное разграничение доступа ко всем методам API.

Диагностика подключения MAX: `python3 scripts/doctor.py`. Сертификаты и пояснения находятся в [certs/README.md](certs/README.md).

### Публичный адрес для проверки жюри

`localhost` доступен только на компьютере, где запущен проект. Для удалённой проверки нужен HTTPS-адрес развёрнутого сервиса. Mini-app и API могут работать на одном домене: nginx уже проксирует `/api/` на backend.

После размещения задайте `PUBLIC_BASE_URL` и `MINIAPP_BASE_URL` равными реальному HTTPS-адресу, настройте URL mini-app в MAX и обновите `base_url` в `artifacts/DATA-API.yaml`. Укажите адрес сервера в техническом слайде презентации.

**В этой версии README публичный адрес сервера не указан: подтверждённого адреса нет в материалах репозитория.**

## 9. Работа с данными

SQLite хранится в Docker volume `classgo-data`. Для PostgreSQL используется `classgo-pg`.

Основные сущности: класс, ученик, контакт законного представителя, событие, выезд, участник выезда, журнал действий и запись о версии документа.

Ответ родителя сохраняет статус, сведения о подписанте, время и источник действия. Покупка билета хранится как отметка пользователя с необязательным номером билета.

Генератор поддерживает приказ и приложения: список участников, реестр согласий, лист инструктажа, маршрутный лист, шаблон уведомления ГИБДД и согласие на обработку персональных данных. Шаблоны содержат поля, которые школа должна заполнить и проверить.

В демонстрации используются модельные сведения. Политика доступа и правовые основания работы с реальными данными должны быть подготовлены до пилота.

## 11. Пошаговая проверка основного сценария

### Через интерфейс

1. Запустите стек и откройте `http://localhost:8080`.
2. Проверьте демонстрационный класс либо импортируйте пример CSV на вкладке «Импорт класса».
3. Откройте «Каталог событий», выберите событие и создайте выезд.
4. Откройте ведомость класса, проверьте статусы и список участников.
5. В «Режиме просмотра» вне MAX откройте экран родителя.
6. Для участника без ответа нажмите «Отпускаю ребёнка», выполните подтверждение и отметьте согласие на обработку данных.
7. Если событие платное, отметьте покупку билета. Вернитесь к ведомости и заново откройте её для получения текущего состояния.
8. Сформируйте приказ и скачайте DOCX/PDF.
9. При подключённом боте проверьте публикацию карточки, личные напоминания и отправку документа в MAX.

Для доставленных напоминаний родитель должен быть привязан к боту. Без токена проверка браузерного сценария не подтверждает доставку сообщений в MAX.

Подробнее: [DEMO.md](docs/DEMO.md), [qa/manual-qa.md](qa/manual-qa.md).

### Через Swagger

Откройте `http://localhost:8080/docs`, выберите метод, нажмите **Try it out**, заполните параметры и нажмите **Execute**. Сначала получите реальные ID класса, события, выезда и ученика: не подставляйте произвольные числа.

## 12. API и ожидаемое поведение

Метод API — действие backend, которое вызывает интерфейс. `GET` получает сведения, `POST` создаёт данные или запускает действие. `{id}` в таблице означает идентификатор соответствующего объекта.

| HTTP | Путь | Назначение |
|---|---|---|
| GET | `/healthz` | Проверить доступность backend |
| GET | `/api/v1/meta` | Описание решения и происхождения данных |
| GET | `/api/v1/classes` | Получить классы и учеников |
| GET | `/api/v1/classes/{id}/roster` | Получить состав класса |
| POST | `/api/v1/classes/import` | Импортировать класс из файла, multipart |
| GET | `/api/v1/culture-events` | Получить каталог с фильтрами |
| GET | `/api/v1/excursions` | Получить выезды |
| POST | `/api/v1/excursions` | Создать выезд |
| GET | `/api/v1/excursions/{id}` | Получить карточку выезда |
| GET | `/api/v1/excursions/{id}/dashboard` | Получить «Светофор» |
| GET | `/api/v1/excursions/{id}/participants` | Получить данные участников выезда |
| POST | `/api/v1/excursions/{id}/consent` | Зафиксировать согласие или отказ |
| POST | `/api/v1/excursions/{id}/ticket-confirm` | Зафиксировать отметку о билете |
| POST | `/api/v1/excursions/{id}/publish` | Опубликовать карточку в MAX, `chat_id` в query |
| POST | `/api/v1/excursions/{id}/remind-unconfirmed` | Отправить адресные напоминания |
| GET | `/api/v1/documents/attachments` | Список доступных приложений приказа |
| POST | `/api/v1/excursions/{id}/export-order` | Получить ссылки на документы и номер версии |
| GET | `/api/v1/excursions/{id}/export-order` | Скачать документ, `fmt=docx` или `fmt=pdf` |
| POST | `/api/v1/excursions/{id}/send-order` | Отправить документ файлом в MAX |
| GET | `/api/v1/excursions/{id}/participants.csv` | Скачать CSV участников |
| GET | `/api/v1/excursions/{id}/calendar.ics` | Скачать календарное событие |
| GET | `/api/v1/excursions/{id}/emergency-contacts` | Получить контакты законных представителей |
| POST | `/api/v1/students/{id}/link-code` | Создать код привязки к боту |
| GET | `/api/v1/parent/context` | Получить детей родителя по `max_user_id` |
| POST | `/api/v1/max/validate-init-data` | Проверить подпись стартовых данных MAX |
| POST | `/api/v1/admin/reset-demo` | Сбросить статусы демо-выезда |
| POST | `/webhook/max` | Принять обновление MAX |

Точный контракт: [artifacts/openapi.yaml](artifacts/openapi.yaml), [artifacts/openapi.json](artifacts/openapi.json). Текущая спецификация запущенного backend доступна на `/openapi.json`. План обязательных проверок: [artifacts/DATA-API.yaml](artifacts/DATA-API.yaml).

### Примеры запросов

Получение классов и событий:

```bash
curl http://localhost:8080/api/v1/classes
curl 'http://localhost:8080/api/v1/culture-events?free=true&sort=date'
```

Создание выезда. Замените ID на значения из предыдущих ответов:

```bash
curl -X POST http://localhost:8080/api/v1/excursions \
  -H 'Content-Type: application/json' \
  -d '{"class_id":1,"culture_event_id":1,"gathering_time":"09:00","return_time":"15:00"}'
```

Ожидается HTTP `201` и карточка созданного выезда. Для ответа родителя замените ID выезда в пути и `student_id` на ученика из этого класса:

```bash
curl -X POST http://localhost:8080/api/v1/excursions/1/consent \
  -H 'Content-Type: application/json' \
  -d '{"student_id":1,"status":"APPROVED","parent_name":"Демо-родитель","pdn_consent":true,"source":"api"}'
```

Первое решение возвращает `changed: true`. Повторное решение для того же участника возвращает `changed: false` и не перезаписывает сохранённый ответ.

Скачать PDF приказа:

```bash
curl 'http://localhost:8080/api/v1/excursions/1/export-order?fmt=pdf' \
  --output order.pdf
```

Несуществующий объект возвращает `404`, некорректный формат параметров обычно `422`. При отправке документа проверяйте `delivered`, а не только HTTP `200`. Функция публикации карточки в текущем демо может вернуть `ok: true` при выключенном боте; это не доказательство доставки в MAX.

## 13. Ограничения и допущения MVP

- Полноценная авторизация, разграничение ролей и изоляция школ на REST API не реализованы. Демонстрационный доступ не подходит для реальных персональных данных.
- Каталог модельный, без синхронизации с актуальным источником.
- Запись ответа родителя фиксирует действие и время. MVP не подтверждает юридическую равнозначность такого ответа бумажному согласию; порядок применения требует отдельной проработки со школой.
- Шаблоны документов требуют заполнения недостающих полей и проверки ответственными сотрудниками школы.
- Отметка о билете не подтверждает оплату автоматически. Сервис не принимает деньги.
- Профиль PostgreSQL есть в конфигурации, но горизонтальное масштабирование требует дальнейшей работы с доступом, миграциями, очередями и эксплуатацией.
- Кабинет администрации и сводная аналитика школы не входят в MVP.
- При действующем правиле первый ответ блокирует последующие изменения. Изменение решения родителя требует отдельного продуктового сценария.
- ICS в текущей реализации использует интервал 09:00–15:00; введённое время сбора попадает в описание, но не определяет фактическое начало календарного события.

Ожидаемая экономия времени и сроки сбора группы — гипотезы для пилота, а не результаты проведённого исследования. План: одна школа, 3–5 классов, одна четверть с замером времени до и после. Масштабирование описано в [SCALING.md](docs/SCALING.md), допущения — в [PRODUCT_RESEARCH.md](docs/PRODUCT_RESEARCH.md).

## 14. Остановка и повторный запуск

```bash
# Остановить контейнеры, сохранив данные
docker compose down

# Повторный запуск
docker compose up -d --build

# Логи
docker compose logs -f backend
```

**Полный сброс удаляет данные в Docker volumes**, включая импортированные классы:

```bash
docker compose down -v
docker compose up -d --build
```

Для стека с PostgreSQL используйте `--profile postgres` и при остановке, и при запуске.

## 15. Тестирование и материалы сдачи

В репозитории есть проверки API, бизнес-правил, адаптера MAX, Bridge, интерфейса и сквозных сценариев. GitHub Actions запускает backend, frontend и сценарий бота с эмулятором MAX.

### Подготовка локального окружения тестов

Из корня репозитория, с Python 3.13 и Node.js 20:

```bash
python3.13 -m venv backend/.venv313
backend/.venv313/bin/python -m pip install -r backend/requirements.txt
cd miniapp
npm ci
cd ..
```

### Отдельные наборы

```bash
# Backend, из каталога backend
cd backend
.venv313/bin/python -m pytest -q
cd ..

# Frontend
cd miniapp
npm test
cd ..

# Бот с эмулятором MAX
backend/.venv313/bin/python scripts/e2e_agent.py

# Сквозная проверка запущенного Docker-стека
backend/.venv313/bin/python scripts/e2e_docker.py http://localhost:8080
```

Браузерные проверки требуют запущенного стека:

```bash
cd ui-e2e
npm ci
npx playwright install chromium
npm test
```

Общий запуск: `./scripts/run_all_tests.sh` или `./scripts/run_all_tests.sh --fast`. Скрипт ожидает `backend/.venv313`, установленные frontend-зависимости и использует nvm для выбора Node.js 20. Если nvm нет, запускайте отдельные наборы командами выше. Полный скрипт также использует `python3` для HTTP-проверок; соответствующие зависимости должны быть доступны этому интерпретатору.

Текущий результат подтверждается фактическим прогоном, а не количеством тестов в описании. Подробности: [TESTING.md](docs/TESTING.md), [REQUIREMENTS.md](docs/REQUIREMENTS.md), [PERFORMANCE.md](docs/PERFORMANCE.md).
